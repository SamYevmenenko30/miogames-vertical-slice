# SPEC: MIO-007 — gamification: claim an entitlement exactly once and draw a verifiable outcome

Card: board/1-in-spec/MIO-007-the-spin.md · Revision 1 · Author: agent (Claude), 2026-11-20

## Context

Step 4 and 5 of Part B, the concurrent-spin case of Part C, and the anti-manipulation answer, all
in one endpoint. Governed by [ADR-0004](../decisions/ADR-0004-server-authoritative-deterministic-draw.md).

## Decisions taken here

- **The player API needs a token, and the operator mints it server to server.**
  `POST /v1/sessions` takes the operator's API credentials and an external player id and returns
  a short-lived player token. Accepting an operator-issued JWT instead would mean trusting ten
  signing schemes and ten key rotations.
- **The outcome is `weightedPick(pinnedVersion.slices, uniform01(serverSeed, spinId))`.** Nothing
  the client sends is an input — not a client seed, not a stake, not a timestamp.
- **The entitlement is claimed by a conditional UPDATE.** Concurrency is settled by the database.
- **The seed is revealed in the response.** The hash was committed at grant time, so a player can
  recompute the draw and see we did not choose the outcome after the fact.

## Behaviour spec

- **S1 — a spin claims one entitlement, draws, credits coins and answers.**
  `POST /v1/spins` with a valid player token answers `200` with the slice id, the prize, the new
  balance, and the entitlement's remaining count. The entitlement moves to `consumed`.
- **S2 — the outcome is determined by the seed and the spin id.** Given a known seed and spin id,
  the slice is exactly the one `weightedPick(slices, uniform01(seed, spinId))` names — asserted by
  recomputing it in the test from the values the response reveals.
- **S3 — nothing the client sends changes the outcome.** A request body carrying `clientSeed`,
  `stake` or `preferredSlice` produces the same outcome as an empty body for the same entitlement.
- **S4 — two concurrent spins on one entitlement: one wins.** Exactly one answers `200`; the
  other answers `409` `spin.no-entitlement`. One spin row exists and the coins are credited once.
- **S5 — no claimable entitlement is a 409 with a machine-readable type**, not a 404 and not a
  200 with an empty prize.
- **S6 — an expired entitlement is not claimable.** Moving the clock past `expiresAt` makes the
  spin answer `409` even though the row is still `granted`.
- **S7 — the coins and the spin are one transaction.** The credit carries idempotency key
  `spin:<spinId>`, and a failure after the draw leaves neither a spin row nor a credit.
- **S8 — the response reveals what is needed to recompute the draw**: `spinId`, `seed`,
  `seedHash`, `wheelVersion` and `sliceId`, and `sha256(seed)` equals the committed `seedHash`.
- **S9 — the spin is recorded for audit.** A `gamification.spin` row stores the entitlement, the
  wheel version, the seed, the seed hash, the slice id and the prize.
- **S10 — a session token is minted by the operator, scoped to one player.**
  `POST /v1/sessions` with the operator's credentials returns a token; a token for tenant A does
  not spin under tenant B, and an unknown external player id is `404`.
- **S11 — tenant isolation.** Tenant B's player with the same external id has its own
  entitlements; spinning as B never consumes A's.

## Open questions

- **Q1 — what if the wheel version an entitlement pinned was deleted?** → **Answered** (agent
  default, 2026-11-20): it cannot be. `wheel_version` is append-only (MIO-006) and nothing
  deletes a wheel while entitlements reference it. The spin reads the pinned version directly and
  fails loudly if it is missing, which would be a corruption rather than a case to handle.
- **Q2 — is a losing slice (`nothing`) a successful spin?** → **Answered** (agent default,
  2026-11-20): yes. It answers `200`, consumes the entitlement, records the spin and credits no
  coins. A wheel with no losing slice is a wheel nobody needs odds for.

## Out of scope

- Spending coins (MIO-009), rate limiting (TD-0005), free-spin prizes being issued to the
  operator (MIO-010 handles issuance; a `free_spins` wheel prize is recorded, not issued, in this
  slice — stated in the README's assumptions).
