# SPEC: MIO-003 — integration: two operator dialects, one canonical deposit event

Card: board/1-in-spec/MIO-003-operator-dialects.md · Revision 1 · Author: agent (Claude), 2026-11-20

## Context

Two operators send "a player deposited" in different shapes and expect reward issuance in
different shapes. There will be ten of them. This is the card that decides whether operator #10
costs a day or a sprint, so the dialect must be the only thing that varies.

Governed by [ADR-0002](../decisions/ADR-0002-canonical-events-operator-dialects.md). This card
covers the **inbound** half; the outbound reward API is MIO-010.

## Decisions taken here

- **Operator A is flat REST with major-unit decimal strings**:
  `{"event":"deposit.completed","event_id":"…","user_id":"…","amount":"50.00","currency":"EUR","occurred_at":"…"}`.
- **Operator B is an envelope with minor units**:
  `{"meta":{"eventId":"…","type":"PLAYER_DEPOSIT","emittedAt":"…"},"payload":{"playerRef":"…","amountCents":5000,"ccy":"EUR"}}`.
- **Money crosses every boundary as minor units plus a currency**, never a float and never a
  bare number. The conversion happens in the adapter, where the dialect is known.
- **The simulated operators duplicate their own dialect** in `src/mocks/casino-platform` rather
  than importing our adapters. A mock that shares code with the translator under test cannot
  catch a translation bug.

## Behaviour spec

- **S1 — the canonical event has one schema.** `casino.deposit.observed` is a Zod schema in
  `src/contracts/events`, carrying `operatorEventId`, `externalPlayerId`, `amount`
  (minor units + currency), `occurredAt` and `operator`. Parsing a payload missing any of them
  fails.
- **S2 — operator A's dialect translates.** A's flat deposit becomes the canonical event with
  `amount.amountMinor = 5000` for `"50.00"` EUR, and `operatorEventId` taken from `event_id`.
- **S3 — operator B's dialect translates to the same thing.** B's envelope with
  `amountCents: 5000` produces a canonical event equal to A's in every field except `operator`.
- **S4 — a malformed payload is refused with a named reason.** A missing or empty `user_id`,
  a negative amount, an unknown currency and a non-ISO timestamp each produce a translation
  failure that names the offending field, not a thrown `TypeError`.
- **S5 — an unsupported event type is refused distinctly from a malformed one.** A's
  `{"event":"withdrawal.completed"}` is reported as *unsupported*, which the caller may ignore;
  a broken deposit is reported as *invalid*, which the caller must not.
- **S6 — money arithmetic never touches a float.** `"50.00"`, `"0.01"`, `"1234567.89"` and
  `"50"` convert exactly; `"50.001"` is refused as more precision than the currency has.
- **S7 — the registry resolves a dialect by the tenant's operator code.** An unknown operator
  code is a configuration error naming the code, raised at resolution, not a silent fallback to
  the first adapter.
- **S8 — no operator name leaks out of this module.** The strings `casino-a` / `casino-b` appear
  only under `src/modules/integration`, `src/mocks` and tests — never in `gamification`,
  `ledger`, `rewards` or `ingestion`.
- **S9 — the simulated operators behave like real ones, badly on request.** The mock serves both
  dialects over HTTP and, per request, can be told to delay, to return 500, or to return a body
  that is not the dialect at all — which is what MIO-010's timeout and failure tests need.

## Open questions

- **Q1 — what if an operator's events carry no stable event id?** Deduplication depends on one.
  → **Answered** (agent default, 2026-11-20): the adapter refuses the event as *invalid* rather
  than synthesising an id from the payload. A synthesised id makes two genuinely different
  deposits collide, which silently swallows a real deposit — worse than refusing. Onboarding an
  operator without event ids is a commercial conversation, and the adapter is where that pain
  belongs (ADR-0002).
- **Q2 — do we trust the operator's `occurred_at`?** → **Answered** (agent default, 2026-11-20):
  we store it as the operator's claim and use our own clock for everything we decide. A rule that
  depended on operator time would be manipulable by operator clock skew.
